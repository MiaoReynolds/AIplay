PipesHub vs OpenViking

名字像、都开源、都能喂给 Agent —— 但它们不是同类产品。PipesHub 是给公司用的企业搜索，OpenViking 是给 Agent 用的记忆与上下文数据库。选错方向，试用一周也试不出结果。

场景 B · 公司知识库 / 企业搜索

PipesHub 完胜。 50+ SaaS 连接器、权限继承、块级引用、Apache-2.0 —— 这正是它设计来做的事。

场景 A · 个人 Obsidian 7000+ 笔记

看你要什么。 要 Agent 长期记忆选 OpenViking；要真人搜索界面 + Drive 实时同步，选 PipesHub。

PipesHub

开源版 Glean —— 企业上下文层 + 企业搜索平台。连接器把每个数据源连同它的权限一起同步，回答走 Agent 循环：计划 → 调工具 → 读结果 → 再迭代，不是单次检索生成。

Apache-2.0v1.0.0 Stablelocalhost:3000Neo4j / ArangoDB + Qdrant

它强在哪

  • 50+ 连接器：Google Drive、Gmail、Slack、GitHub、Notion、Jira、Confluence、M365、SharePoint、Salesforce、Zendesk 等，实时 + 定时索引，只读不改源。
  • 权限继承：“在 Drive 里看不到的文档，在 PipesHub 里也搜不到。” Agent 以具体个人 PAT 身份连接。
  • 块级引用：精确到页码、段落、原文链接；POST /api/v1/retrieve 返回带引用的 chunk。
  • 混合检索：语义 + 关键词 + grep 精确匹配 + 知识图谱导航 + 全文阅读；1.0 新增 GitHub/GitLab 代码图谱。

本地 / Obsidian 怎么接

  • 无 Obsidian 连接器。两条路：① UI 里 Knowledge Base 直接上传少量 .md / .txt / PDF；② Local FS 连接器 + Docker bind-mount（如 /data/demo）。
  • Drive 里的库可走 Google Drive 连接器（Markdown 是可索引格式），但 wikilink / backlink 处理未在任何来源中验证。

OpenViking

给 AI Agent 用的上下文数据库 —— “Agent 所知的一切，一个文件系统装下：知识、记忆、技能”。内容组织成可浏览的 viking:// 虚拟文件系统，人可以打开任意目录检查、编辑 Agent 到底知道什么。

AGPL-3.0 主项目0.5.4 · pre-1.0localhost:1933火山引擎 / ByteDance 维护

它强在哪

  • 三级分层加载（核心思想）：L0 摘要约 100 tokens → L1 概览约 2,000 tokens → L2 全文按需加载。Agent 先扫 L0，只在相关处下钻。
  • 目录递归检索（TrieHI）：先定目录范围、再在范围内做向量排序；find 直接查，search 结合会话上下文规划检索。
  • 记忆自进化：会话提交后自动归档并抽取记忆为 Markdown，写入 viking://agent/memories/，无需人工整理。
  • Agent 集成最广：Claude Code、Codex、Cursor、TRAE、OpenClaw、Hermes（内置）、OpenCode、LangChain 等。

本地 / Obsidian 怎么接

  • ov add-resource ./<folder> 原生导入 Markdown 文件夹，结构保留。
  • 致命 caveat：本地导入是静态快照，不支持 watch_interval > 0，源文件变了必须重新导入 —— 每天在变的 7000 篇库没有实时同步。

试用命令

uv tool install openviking && openviking-server init

放到你的两个场景里

结论按你的实际用法排，不是按功能多少排

A · 个人 Obsidian 库（7000+ 篇，Google Drive 同步）

两者都不是开箱即用：都没有 Obsidian 连接器，wikilink / backlink / frontmatter 保真度都未验证 —— 必须先拿样本测。

1

OpenViking —— 若你要的是 Agent 记忆本地文件夹是它的原生路径，L0/L1 摘要正是为“快速扫 7000 篇而不全量加载”设计的；安装也轻得多。代价：只能指向磁盘上的 Drive 同步文件夹（无 Drive 连接器）、导入是快照要定期重导、每篇都要 VLM 生成摘要（7000 篇的成本/时间未量化）、AGPL 个人内部用没问题。

2

PipesHub —— 若你要真人搜索界面Drive 连接器是两者中唯一的实时同步路径，还带搜索 UI + 块级引用。代价：为一个人的本地笔记问题扛起 16 GB 的多数据库重栈；Local FS 还要 Docker bind-mount。若 A、B 共用一个实例，才值得。

B · 小公司知识库 / 企业搜索（给客户做定制软件）

这一项没有悬念，类别差距，不是功能差距。

1

PipesHub —— 明确首选50+ 连接器（Drive/Slack/Gmail/GitHub/Notion）、权限继承（多人/多客户时是刚需）、块级引用（客户-facing 回答必须可核查）、给非技术员工的搜索 UI、Apache-2.0 可安全嵌入你卖给客户的专有软件。Community 自托管 $0（二手来源）可把客户数据留在自己 VPC。

—

OpenViking —— 不适合做公司 KB 本体无 Slack/Gmail/Drive/Notion 连接器，公司知识只能手工导出再导入；权限是手动 ACL 而非继承；Studio 是给开发者看上下文的，不是企业搜索 UI；AGPL-3.0 在“通过网络向客户提供专有软件”时会触发源码开放义务，需商业版或许可证审查。它正确的位置是在 PipesHub 之上，给你自己造的 Agent 当记忆层。

试用路线：有空照这个顺序试

不要第一天就拿真库试

STEP 1

先定优先级

B 优先（或库在 Drive 且想要 UI+引用）→ 先试 PipesHub。A 的 Agent 记忆优先、且习惯终端/Claude Code → 先试 OpenViking。

STEP 2

只用样本文件夹

复制 50–200 篇有代表性的笔记（长短不一、带 wikilink、frontmatter、附件，再加几个 PDF/图片）到临时文件夹。PipesHub 用 KB 上传最简单；OpenViking 用 ov add-resource ./sample --to viking://resources/sample --wait。

STEP 3

测四件事

① 索引耗时 + 模型成本；② wikilink / frontmatter 是否存活；③ 一个已知事实能否被检回；④（PipesHub）引用是否指到正确的块。测不过，换另一个，不要硬调真库。

⚠

许可证坑：OpenViking AGPL-3.0

个人/内部自托管没问题；一旦把它作为网络服务嵌进卖给客户的专有软件，就会触发 AGPL 的源码共享义务，或需要付费 Self-Managed 商业版。PipesHub Apache-2.0 无此问题。README 还注明：整体改写/重新开源被禁止，大段翻译需火山引擎书面授权（二手报道称其 2026-03 由 Apache 改为 AGPL）。

◐

装之前先过的三关

Docker：PipesHub 必须 Docker + Compose v2 且约 16 GB 内存，先查 docker info 与空闲内存；OpenViking 可不用 Docker（uv 安装）。模型：PipesHub 先把 Ollama 配好（端点 http://host.docker.internal:11434），否则搜索报 500；OpenViking 需嵌入 + VLM 都配。版本：两者都锁版本试 —— PipesHub 锁 1.0.0，OpenViking 按 PyPI 的 0.5.4 锁。

另外两个提醒：① PipesHub 的 Drive/Slack/Gmail 连接器需要逐个走浏览器 OAuth —— 等样本试用证明检索质量后再连真实工作区，不要先连。② 若考虑 OpenViking 托管版，其服务端点在北京（api.vikingdb.cn-beijing.volces.com），README 称中国以外托管（BytePlus）仍在规划中 —— 在新加坡用要考虑数据驻留；自托管可绕开。PipesHub Cloud 的数据位置在已读来源中未说明，自托管同样可绕开。

还没查清的（别当结论用）

  • 价格：PipesHub 2026-11-10 未找到官方价格页，Community $0 / Enterprise 询价来自二手目录（数据核查于 2026-09-21）；OpenViking 超过 50 文件的托管价与 Self-Managed 价均无公开数字。预算前需向官网/销售确认。
  • Obsidian 保真度：两家都未文档说明 wikilink、backlink、frontmatter、.obsidian/ 的处理 —— 只能靠样本试用实测。
  • 7000 篇的规模成本：两家都未公布 7000 文件的索引时间/成本；PipesHub 的 16 GB 下限与 OpenViking 的逐文件 VLM 摘要都要在样本上实测外推。
  • OpenViking 版本线：仓库有 110 个 release、多条版本线（追踪站还出现过 0.2.0）；已核实的核心最新版以 PyPI 0.5.4（2026-11-09）为准，锁版本时认 PyPI/GitHub tag，不要认“latest”追踪站。
  • 厂商基准：PipesHub 的 EnterpriseRAG-Bench #1/39（93.24）与 OpenViking 的 LoCoMo 80–83% 均为厂商/相关方报告，未独立复现，只作上限参考。
