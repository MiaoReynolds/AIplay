01 / Inference engines

先把模型“跑起来”

Ollama、vLLM、SGLang 处于模型服务环节。它们不是 Agent 框架，也不负责知识索引、权限或业务工作流。

本地开发

Ollama

让个人和小团队方便地在本地运行模型，适合原型、测试与轻量部署。

高吞吐服务

vLLM

面向大量并发请求的推理引擎。代表性创新是 PagedAttention，以分页方式管理 KV Cache。

复杂生成

SGLang

高性能推理与结构化生成，代表性创新是 RadixAttention，强调共享前缀的缓存复用。

04 / Five opportunities

五个值得深入的方向

机会集中在模型变强后仍需存在的系统能力：状态、身份、外部执行、证据与成本控制。

01
重点关注

Agent Memory & Context OS

从聊天记录、摘要和向量检索，走向可长期维护事实、时间关系、来源、矛盾与权限的记忆层。

  • 带版本与证据溯源的记忆
  • 跨 Agent 共享与动态上下文构建
  • 低成本增量更新
02
企业部署前提

Agent Secure Runtime

Agent 会执行代码、操作浏览器、发送邮件，甚至付款；提示词不能代替强制安全边界。

  • 按任务隔离的沙箱
  • 细粒度权限与凭证隔离
  • 审批和可审计执行记录
03
可靠执行

Durable Agent Execution

任务可能运行数小时，期间需等待人类审批并从中断中恢复。

  • 可靠状态机与持久执行
  • 失败恢复、重试和回滚
  • 外部系统一致性
04
证明工作正确

Agent Evaluation & Verification

最终答案正确，过程仍可能泄密、误调工具或违反规则；验证应覆盖全过程。

  • 任务级验证和自动案例
  • 轨迹回放与证据一致性
  • 基于真实结果的质量评价
05
单位任务成本

Inference Optimization

不仅追求 Token/s，还要优化每项有效任务的计算成本与等待时间。

  • 任务感知模型路由
  • 跨请求 KV Cache 共享
  • 异构 GPU 与长上下文调度
共同评价框架

看“完成任务”的成本与可信度

对企业客户，系统会不会丢记录、错引文件、泄露资料或执行错误操作，往往比模型榜单上的分数更直接。

准确率恢复率证据覆盖权限合规单位成本

06 / Investment lens

投资潜力 ≠ 创业切入难度

推理引擎技术价值很高，但常需要 GPU Kernel、CUDA、分布式系统能力与硬件测试资源。企业上下文、记忆和评测可用较少硬件先验证，再通过真实部署积累壁垒。
